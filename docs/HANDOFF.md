# Перенос незаконченной сессии между Маком и телефоном

Сессии Claude Code хранятся **локально** на той машине, где вы работали:
`~/.claude/projects/<путь-проекта>/<session-id>.jsonl`. Между Маком и
Claude Code в вебе (телефон) эти файлы не синхронизируются — веб-сессия
поднимается в одноразовом контейнере, где есть только свежий клон репозитория.
Поэтому на телефоне история с Мака и не видна.

Этот механизм переносит её сам: после каждого хода сессия сохраняется в
служебную ветку `claude-handoff`, а при старте сессии на другой машине —
подкладывается в контекст.

## Что переносится

- хвост диалога (ваши сообщения, ответы Claude, вызовы инструментов);
- список задач (`TodoWrite`) в том состоянии, в каком его застали;
- какие файлы правились;
- ветка и HEAD-коммит;
- **патч незакоммиченных правок** — то есть сама незаконченная работа, а не
  только разговор о ней;
- **новые файлы, ещё не добавленные в git** — целиком, содержимым.

Не переносятся: двоичные файлы, файлы больше 64 КБ и всё, что попадает под
`.gitignore` (в том числе `.env` с боевыми токенами). Про каждый пропущенный
файл в переносе будет строка — молча ничего не теряется.

Предыдущий перенос не затирается: в ветке лежат `handoff.enc` (последний) и
`handoff.prev.enc` (предыдущий), достать его — `load --prev` / `patch --prev`.

## Безопасность

Репозиторий публичный, поэтому в GitHub уходит **только шифротекст**:
ключ выводится через PBKDF2-SHA256 (200 000 итераций), шифрование — потоковое
на HMAC-SHA256 в режиме счётчика, целостность — HMAC поверх шифротекста
(encrypt-then-MAC). Без `HANDOFF_KEY` из ветки не достать ничего.

Дополнительно, до шифрования, из текста вырезаются похожие на секреты строки
(`sk-ant-…`, токены телеграм-бота, `ghp_…`, присваивания вида `TOKEN=…`).

Ветка `claude-handoff` живёт отдельно от кода: в ней всегда ровно один коммит
без истории, она никогда не мержится в `main` и не попадает в PR.

## Настройка (один раз)

### 1. На Маке — создать ключ

```bash
cd путь/к/trofim-bot
python3 scripts/handoff.py keygen
```

Команда положит ключ в `~/.claude/trofim-handoff.key` (права 600, вне
репозитория) и напечатает его значение.

### 2. В вебе — прописать тот же ключ

claude.ai/code → настройки окружения (Environments) → переменные окружения:

```
HANDOFF_KEY=<значение из keygen>
```

### 3. Разрешить хуки

При первом запуске в каталоге проекта Claude Code спросит, доверяете ли вы
`.claude/settings.json`. Ответьте да — иначе хуки не запустятся.

Готово. Дальше всё само.

## Как этим пользоваться

**С Мака на телефон.** Просто закройте ноутбук. Последний ход уже сохранён
(Stop-хук, не чаще раза в 45 секунд). Откройте сессию в вебе на этом
репозитории — Claude начнёт с выжимки: где остановились, что в плане, что
не закоммичено. Чтобы получить сами правки в рабочее дерево:

```bash
python3 scripts/handoff.py patch --apply
```

**Явно сохранить с заметкой** — слэш-команда прямо в сессии:

```
/handoff застрял на парсинге голосовых, дальше — таймауты
```

**С телефона на Мак** — то же самое, механизм двусторонний.

## Команды

| Команда | Что делает |
|---|---|
| `python3 scripts/handoff.py save --note "…"` | сохранить сессию в перенос |
| `python3 scripts/handoff.py load` | показать, что сейчас в переносе |
| `python3 scripts/handoff.py patch` | показать незакоммиченную работу |
| `python3 scripts/handoff.py patch --apply` | разложить её в рабочее дерево |
| `python3 scripts/handoff.py load --prev` | предыдущий перенос, если последний уже не тот |
| `python3 scripts/handoff.py clear` | очистить перенос (работа закончена) |
| `python3 scripts/handoff.py keygen` | создать ключ шифрования |

## Если что-то не так

- **В новой сессии тишина, переноса нет.** Посмотрите
  `.claude/handoff/hooks.log` и `.claude/handoff/autosave.log`. Частая причина —
  не задан `HANDOFF_KEY` на этой стороне.
- **«не удалось расшифровать».** Ключи на машинах разные. Сверьте значение
  `HANDOFF_KEY` с содержимым `~/.claude/trofim-handoff.key` на Маке.
- **Патч не накладывается.** Значит дерево уехало относительно той машины.
  Посмотрите глазами: `python3 scripts/handoff.py patch`.
- **Подкладывается уже сделанная работа.** `python3 scripts/handoff.py clear`.
- **Отключить автосохранение** (разово): `HANDOFF_AUTOSAVE=0`.

## Что механизм не делает с вашей машиной

Это стоит знать, раз он работает сам после каждого хода:

- **Не трогает рабочее дерево и индекс.** Коммит в ветку переноса собирается
  git-плюмбингом (`hash-object` → `mktree` → `commit-tree`), никаких
  `add`/`commit`/`checkout`/`stash`. Единственное место, где на диск что-то
  пишется, — явная команда `patch --apply`, и та не перезаписывает
  существующие файлы.
- **Не трогает ваши ветки и историю.** Пишет только в `claude-handoff`, где
  всегда один коммит без родителя.
- **Не блокирует сессию.** Сохранение уходит в отдельный процесс; хук
  возвращается за ~0.05 с. Нет сети — фоновый процесс отвалится сам через
  ~14 секунд и напишет строку в `.claude/handoff/autosave.log`.
- **Не спрашивает пароль.** `GIT_TERMINAL_PROMPT=0` и закрытый stdin: если git
  вздумает запросить учётку, он упадёт, а не повиснет навсегда.
- **Не пишет в репозиторий локально.** Всё локальное — в `.claude/handoff/`,
  которая в `.gitignore`.

Худшее, что может случиться при сбое: перенос не обновится, и на второй машине
вы увидите состояние на несколько минут раньше. Локальная история сессии на
Маке (`~/.claude/projects/…`) при этом остаётся нетронутой в любом случае —
механизм только читает её.

## Границы

Это перенос **контекста**, а не состояния модели: на второй машине начинается
новая сессия, которой подробно рассказали, что было в прошлой. Дословной
истории и внутренних рассуждений там нет — их не существует за пределами
исходной машины.
