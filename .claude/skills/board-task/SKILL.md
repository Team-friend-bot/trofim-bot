# Задача з борда: від «взяв» до «автор підтвердив»

**Навіщо цей порядок.** З 428 закритих задач 28 повернули автори. Майже жодна —
не баг у коді. Це «зробив не те / не там / не в тому вигляді»: #387 три повернення
поспіль (блок не в тому місці), #366 вигадане розмежування каналів, яке вже було в 1С,
#363 переробка на 100+ годин через самостійно вигадане бізнес-правило.
Два речення ДО роботи і один доказ ПІСЛЯ знімають майже все це.

## 0. Знайти задачу і звірити, що це САМЕ вона

```
ssh root@167.71.1.243 "/opt/venv/bin/python /opt/manager_tracker/scripts/notify_task.py list"
… notify_task.py show <id>      # повний тред: автор, текст, попередні репліки
```

Автор і текст мають збігатися з тим, що просять зробити. Якщо задачу ставили усно
(не з борда) — цей навик не потрібен, нічого слати.

## 0.5. Прочитати профіль ЦЬОГО замовника (10 секунд)

```
ssh root@167.71.1.243 "cat /opt/scripts/task_authors.md"    # оновлюється щодня о 6:45
ssh root@167.71.1.243 "cat /opt/scripts/task_lessons.md"    # уроки з усіх повернень
```

Там зібрано те, що людина вже була змушена пояснювати мені двічі. Приклади живих
профілів: Вікторія двічі повертала через застарілий склад команди («Ірина більше не
працює») — тож перед будь-якою задачею про менеджерів звіряти `name_audit.py`.
Леся найчастіше повертає через **вигадане бізнес-правило** — у неї джерело правди 1С.
Настя повертає через **місце і вигляд блоку** — питати зразок («як блок Х»).

## 1. ДО коду — три питання і звірка розуміння

Задача у два рядки від людини = **не ТЗ, а натяк**. Перед першою правкою відповісти собі:

1. **Де саме зʼявиться** — сторінка, вкладка, блок. Не «на борді».
2. **За яким зразком** — на що має бути схоже з того, що вже є.
3. **Звідки дані** — і чи не лежить це правило вже в 1С. Бізнес-правила
   (хто чий клієнт, хто ще працює, як діляться канали) **не вигадувати** — питати або брати з 1С.

Тоді — публічно звірити з автором, **першим кроком будь-якої нетривіальної задачі**:

```
… notify_task.py start <id> \
    --understood "перелічу показники первинки окремим блоком" \
    --where "/dashboard/hunters, зверху над таблицею" \
    --show "скрін блоку + цифри за вересень"
```

Автор отримує «🔧 Взяв у роботу. Зрозумів так: … Якщо не так — скажи зараз».
Коштує хвилину; #387 чекав правки 33 години, бо цього кроку не було.

## 2. Робота

Деплой — за навиком `deploy-to-prod` (staging → прод, бекап, ОДИН рестарт наприкінці).
Перед рестартом — `/api/broadcast/active`: рестарт уб'є розсилку менеджера.
Перед правкою `dashboard.py` — `grep` по анкеру: паралельна сесія могла переписати файл.

## 3. Перевірити очима того, хто цим користуватиметься

Не «імпорт пройшов». Відкрити ту саму сторінку в тому самому вигляді, у якому нею
користуватимуться, і звірити конкретні цифри. Якщо блок для Насті — дивитись у
її розділі, а не в API-відповіді.

## 4. Закрити з доказом

```
… notify_task.py done <id> \
    --text "що саме зроблено, людською мовою" \
    --proof "відкрив /dashboard/hunters, блок на місці, 47 первинних за вересень збіглось із 1С"
```

`done` **без `--proof` відмовляє** — так і задумано. `--no-proof` лише свідомо.
Часткова робота без закриття — `reply`. Є `--dry-run`.

## 5. Якщо задачу все ж повернули — зробити з цього урок

Повернення безкоштовне лише тоді, коли з нього щось лишається в системі:

```
ssh root@167.71.1.243 "cd /opt/manager_tracker && /opt/venv/bin/python3 \
  /opt/scripts/task_feedback.py unclassified"      # чого класифікатор ще не розуміє
```

Кожен рядок звідти — привід дописати ключові слова у `RULES`
(`/opt/scripts/task_feedback.py`). Тоді цей тип помилки наступного разу
потрапить у профіль автора автоматично, і я побачу його на кроці 0.5.
Метрика, за якою видно, чи система міцнішає:

```
… task_feedback.py stats --days 90     # % повернень по тижнях
```
Станом на 12.09.2026: 7% за 90 днів, але W36 — 17%, W37 — 13% (задач стало більше,
дисципліна не встигала). Мета — стійко нижче 5%.
Щонеділі о 19:00 власнику йде дайджест: скільки закрито, скільки повернули, через що.

## Пастки

- Здавати тим, що людина **побачить**: назва сторінки/блоку + конкретні цифри, а не «готово».
- `board_inbox.py` запускати ЛИШЕ з `cd /opt/manager_tracker`, ad-hoc SQL по задачах заборонено.
- Блок «❔ ЗАКРИВ, АЛЕ АВТОР НЕ ПІДТВЕРДИВ» в `board_inbox.py` — 25 задач за 14 днів.
  Саме там ховається «зробив не те»: людина мовчки не приймає й переробляє вручну.
  Побачив там свою задачу — не чекати, піти й спитати автора.
- Блок «🗓 ВІДКРИТІ ДАВНО» (>2 дн) — якщо задача висить, вона не забута, а не зроблена.
- **Найдорожчі помилки — не в коді.** З 38 повернень: вигадане бізнес-правило 7,
  не те джерело даних 6, застарілий довідник людей 4, не там/не в тому вигляді 3,
  неповний обсяг 3 — і лише **1 справжній баг**. Тобто ціна питання «а як правильно?»
  на початку вища за будь-яке акуратне програмування.
- Повернення ≠ дефект: «дістань ще список» і «а це як?» — це діалог (10 з 38).
  Не рахувати їх собі в помилки, інакше метрика бреше.
